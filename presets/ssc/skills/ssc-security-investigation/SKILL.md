# 安全调查

目标是找到有证据支持的安全缺陷，并尽快排除错误假设。扫描器是线索来源之一；没有告警也可以从项目自身的不变量发现问题。按任务需要与源码、依赖或构建发布技能结合，不改变用户给定的范围和执行权限。

先区分任务：漏洞调查要证明越过安全边界；普通故障诊断要区分原因。若任务是超时、失败、性能或日志归因，先读 [故障归因](references/causal-analysis.md)，用原因假设报告，不为使用记录工具而虚构攻击者控制或安全影响。发现独立安全假设后再使用下面的四条证据链。

## 建立与任务相关的安全模型

先确定受审版本、相关未提交修改、实际入口和运行配置。围绕目标功能，记录主体及其原有权限、受保护资源或操作、可控输入与调用顺序、信任边界、最终执行限制的组件。包括服务端代理调用者行使的权限；身份可信不代表身份的所有属性、类型或生命周期已经查明。只追踪能改变这些判断的实现和调用者，不先通读整个仓库，也不把完整架构图当成调查前置条件。

把预期写成可核查的关系，例如“任何读取路径返回的对象均归当前主体所有”，而不是“这里应该加权限检查”。注明约束来自文档、调用方契约还是推断；判断它是否真是安全边界、调用者是否早已拥有等价权限。没有规范时可提出待证约束，但不能把个人设计偏好当成产品承诺。模型随源码证据修正，未知前提不要默认为有利于漏洞成立。

## 从实现差异产生假设

用“某种能力的调用者，经某入口和前提，可以使某操作违反某条安全约束”的形式提出具体假设。优先调查低权限可达、影响明确且关键未知条件可验证的路径；每条活动假设都有下一项能改变判断的检查，避免持续搜集相似告警。

围绕同一安全约束，比较实际实现对同一操作、主体或对象的处理：

| 比较对象 | 决定性问题 |
| --- | --- |
| 不同入口、正常与错误/回退分支 | 是否都执行同一约束，或由外层、后端统一强制？缺少本地检查不等于缺少防护。 |
| 检查时与消费时的表示 | 解析、规范化、拼接或间接解析后，最终使用的对象是否仍是获准对象？ |
| 不同组件对身份或对象的比较 | 相等判断、序列化、索引是否保留安全上有意义的区别？先核实实际类型域，不能随意引入不可能的输入。 |
| 冷缓存与热缓存、同步与异步路径 | 快速路径是否保留完整路径的身份、归属和策略限制？ |
| 提交与执行、检查与使用 | 权限、资源归属或状态变化后，决定是否仍有效？先查明产品允许的授权时点与一致性语义。 |
| 单次操作与操作序列 | 各步合法时，重试、重放、并发、撤销或部分失败是否破坏整体约束？调用者能否控制所需顺序？ |

差异是线索，不是结论。根据实际架构选择相关比较，不机械检查全部类别。从敏感操作反向找调用者，再从真实入口正向核实导出、注册、配置、权限前置条件及错误分支；未挂载模块和内部函数不能代替真实入口。路径相同也不保证安全，仍需核查共同实现是否保持约束。

同一根因的多个入口合并为一个问题，保留已验证与未验证的区别。只否定证据覆盖的假设；一条路径被阻断不代表所有入口都安全，也不必为每条被否定假设继续穷举。

## 拆解证明义务与选择下一步

将具体假设展开为“调用者可提供 X → 入口接受 X → 经转换或状态变化 T → 到达敏感操作 S → 防护 G 未阻断 → 结果违反约束 I”。这不是必填长表；只记录决定结论的节点及连接，每处标出观察、推断或未知，并引用文件行号/符号、配置或可重查的运行记录。静态路径分析也可以构成证据，不为形式完整而强制运行实验。

分别回答攻击者控制、执行可达性、防护为何无效、具体安全影响。整体结论依赖哪几个尚未证明的条件，要直接写出来；不能用多个已知事实的数量抵消一个决定性的未知。必要条件被否定才能反驳该假设；没有证明必要条件只能保持未知。复杂路径的整理方法见 [证明义务与分层裁决](references/proof-obligations.md)，需要展开多跳链路、裁决冲突证据或收尾时读取。

主动寻找最强的反解释：上游是否拒绝、后端是否隔离、输入是否已被固定、攻击者是否不能到达、问题是否只存在于特制测试。检查实际实现而不是让第二段文字重复第一段结论。反证未解决时保留条件性判断，不用更强措辞填补证据缺口。

下一次读文件或调用工具前，明确它解决哪个关键未知，以及可能结果如何改变判断。优先检查一旦不成立就能阻断整条假设的低成本条件，例如真实注册、身份来源、后端统一校验；不要只挑容易支持假设的检查。若不同解释对结果的预测相同，该检查不能区分它们。连续操作没有增加决定性证据时，改变方法、暂存候选或交付缺口。明确无法区分原因是有效结果，不需要靠模拟器补齐材料。

## 验证与对照

已获授权进行本地验证时，用无真实凭据、可清理的临时对象和最小输入设计实验；保留命令、环境/版本、预期、实际输出及退出状态。不要为了复现而去掉正在验证的防护、赋予攻击者原本没有的权限，或把宿主与目标进程的权限混为一谈。不擅自执行受审项目脚本、访问外部目标或触发发布。

尽量经真实应用入口观察安全相关结果，并设置正常输入、低权限/高权限或有效防护作为对照。一次只改变决定性变量。内部函数实验可以验证机制，但要明确未证明产品入口可达；扫描成功、进程退出 0 或字符串回显本身不等于安全影响成立。

运行前写清实验对象、唯一变更、预期结果及什么结果会推翻假设。自建程序与目标程序不是同一个对象；前者成功不能补齐后者缺失的实现、配置或可达性证据。对泄漏检查，比较返回对象实际所属主体与请求主体，不用秘密字符串出现与否替代授权判据。测试应导入受审实现，不复制一份自己猜测的实现。

为调查留出交付预算。连续两次修实验仍未触及目标行为时，停止扩建夹具，回到代码证据或更小的区分实验；预算将尽时交付已知、未知和下一步。不要因一个机制值得演示就为它重建整套系统。

复现失败时检查覆盖的路径和前提。环境不符、依赖缺失、错误发生在目标行为之前属于未完成验证；只有实验能够触及并否定必要条件时，才构成反证。用户要求修复时，回归应在缺陷版本失败、修复版本通过，并检查合法操作仍可用。

## 保存与恢复

对值得继续调查的独立候选，在证据发生实质变化或收尾时使用 `security_investigation` 保存；不为每次读文件保存一次，也不伪造扫描器 Finding ID。为四条证据链各提供一条 claim，缺证据时写 unknown；为最强反解释提供 counteranalysis。将可定位的原始观察存入 evidence，推断写在 rationale。记录实际版本和相关工作区修改。

`supported` 是模型基于证据的判断，工具只验证字段及引用完整性，不证明内容真实。它不等于动态复现，更不等于零日；没有运行实验就省略 validation。`refuted` 需要否定必要条件的证据；`inconclusive` 和 `investigating` 要留下能区分结果的 nextCheck。若内部机制已复现但真实入口未知，可以记录 validation=reproduced、status=inconclusive，报告必须保留此边界。

保存契约：caseId 用小写 slug；证据 ID 可用 `E1` 或 `run-1`，大小写敏感，引用必须完全一致。每个 claim、counteranalysis 和 validation 都必须有 evidenceIds；未知可为 `[]`，已解决判断需引用证据。完整最小记录示例见 [记录示例](references/record-example.json)，需要保存时再读。

恢复调查时用 list/get 读取当前会话记录，核对版本、文件和前提后复用。新代码不继承旧结论。已有扫描器告警仍按原工具契约使用 `submit_sast_assessment`，本工具补充独立调查，不把两种记录当作两项漏洞。

分层判断使用现有字段表达：机制和防护写入相应 claim 的 rationale，可达性写入 reachability，越过原有权限的结果写入 security-impact；运行范围写入 validation，缺口写入 nextCheck。新颖性单列于报告。不要新增工具不接受的字段或 claim kind，也不要把分层判断平均成置信分数。工具没有自动核对源码、执行归属或推断有效性；保存成功不能代替这些检查。

## 交付

先回答哪些问题成立、哪些被否定、哪些仍有条件。重要问题分别说明机制是否存在、指定配置下是否可达、是否越过主体原有权限、影响已证到哪里及新颖性是否查证；无需对简单问题强制生成五张表。区分“静态证据支持”“限定条件下复现”“实际入口已验证”，不将 best practice 偏差包装成漏洞。

核对证据与当前版本的联系：引用的代码确实存在，实验使用的是受审实现，所称结果出现在对应输出中。证据过期或条件变化时，重新检查依赖它的结论；行号不稳定时补充符号与代码片段，不编造定位。用户要求修复建议时，说明修复如何恢复约束，并检查是否仍有等价旁路或破坏合法行为；未经验证的方案明确标为建议，不能因诊断正确就宣称修复可靠。

交付前逐项核对决定性主张：原始输出究竟直接显示了什么，是否换了实验对象、加入了材料没有给出的前提，最强反解释是否真的被检查。日志没有后续记录不等于程序没有离开最后阶段；缺少源码不等于源码缺少防护；状态码相同不等于所有侧信道不存在；没有尝试工具不等于已证明权限阻止。若证据只支持推断，修正标题、摘要、表格和存储记录的全部措辞，不能只在末尾追加免责声明。

若任务要求查证新颖性，另行检查维护者公告、公开 issue/discussion、修复提交及受影响版本，记录检索时间和来源。未搜索到公开记录不是未披露证明。没有查证就写“新颖性未查证”；已公开问题不能当作新零日。综合报告说明覆盖缺口，但不为了凑数量制造发现。
