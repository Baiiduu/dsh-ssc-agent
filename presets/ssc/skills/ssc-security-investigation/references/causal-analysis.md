# 故障归因

此模式产出原因分析，不默认产出漏洞记录。使用四列：候选原因、支持观察、冲突或缺失证据、下一项能区分的检查。

先定义要解释的具体运行和现象，注明版本、配置与日志覆盖范围。标出观测到的事件；未记录的时间段保持未知，除非已核实日志是完整且无缓冲的阶段追踪。两条重复路径只能提示重复访问，不能证明目录实际是链接、存在环或执行从未进入后续阶段。

网络获取、启动、规则加载、目标发现和分析执行属于不同阶段。重复超时只加强“该条件下会超时”的观察；没有输出可能来自 quiet 模式、缓冲或采集问题，不能据此定位阶段。连续相同结果没有新增信息时，改查阶段证据或明确阻塞。

保留至少一个能解释同样观察的反假设。只排除与已有证据冲突的必要条件，不把“当前不支持原因 A”转写成“已证明原因 B”。不同运行、不同扫描器版本、不同缓存或规则来源的成功，不是对失败运行的直接因果反证。

优先选择不需要重建系统的小检查，例如核对目标实现、链接元数据、已有时间戳或调用栈。需要实验时，固定实现和环境，每次只改变一个因素；更换规则来源并同时切断网络是两个因素。明确对每个竞争原因分别预期什么结果：若所有原因都预测同样的结果，该实验没有区分力。

自建机制演示只说明“某种实现能产生相似现象”，不说明目标采用该实现。若实现缺失且用户只要求实验设计，无需为了让报告显得充分而构建模拟器。输出直接事实、当前最合理假设和未验证条件；无法区分时明确未决。
