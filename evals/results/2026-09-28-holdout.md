# 新案例三组真实模型对照（2026-09-28）

本轮完成技能、记录工具修订与 36 场真实模型会话。**记录调用错误减少，但没有证明漏洞分析准确率提升。** 排除一道前提不充分的题目后，三组核心通过数均为 10/11。修订版另发现了出题时遗漏的身份类型问题，经复验成立；这是合成材料中的有效新假设，不是真实产品零日漏洞。

## 实现

- 调查技能区分安全缺陷调查与普通故障诊断；增加竞争解释、目标实验与机制演示的边界、反证、预算和最终结论一致性要求。
- 增加 `references/causal-analysis.md` 和可通过真实记录工具校验的 `record-example.json`。
- 证据 ID 接受 `E1` 等大写形式，仍区分大小写；案件 ID 仍为小写 slug。保留重复 ID、悬空引用、状态与证据一致性校验。
- 工具描述明确必填字段、四类主张、证据引用和记录大小限制。工具校验结构，不能代替对模型证据真实性的审查。
- 新增 `scripts/prepare-holdout-eval.mjs`：12 个中性命名案例，答案在材料目录外，10 个可执行检查及正常行为对照。

## 实验设计

使用实际 DSH 工具循环与 `deepseek-official / deepseek-flash`，reasoningEffort 为 `max`。baseline 为原先未加入调查机制的版本；current 为本轮修改前的调查技能与工具；revised 为本轮冻结后的版本。候选代码和技能先冻结，再生成新题，没有根据本轮结果修改候选并重跑。

每组每题运行一次，预算 20 步、300 秒。逐题运行三组并发会话，轮换启动顺序。共 36 场，35 场完成；current 的规范化防护题耗尽 20 步，未交付最终报告，按未完成计，不能称为误判。

五组代码配对覆盖后端对象归属、路由可达性、规范化与权限检查次序、跨用户缓存、排队任务撤权；另外两题检查稀疏日志下的未知结论及阶段完成证据。模型可读工作区使用随机 ID，答案不放入其中；这是提示和目录层面的盲测，**没有操作系统级答案隔离或网络封锁**。工具参数抽查未发现答案/凭据路径访问；这不等于证明所有子进程没有外部访问。扫描器自身联网行为未单独隔离。

## 关键观察

1. 修订版在稀疏日志题仍将“缺少后续日志”和自写模拟器结果用于否定未知目标的循环原因，并保存为 `refuted`。轨迹确认它已读取新技能和因果分析参考，问题不是加载了旧版本。这是需要优先解决的证据推断错误。
2. 另一道阶段日志题中，修订版正确使用 discovery complete 反驳“仍卡在枚举”，保留死锁原因未知，并放弃无法验证目标原因的合成实验。说明新要求有时生效，但不稳定。
3. 缓存防护题原答案只验证字符串身份。TASK 没有规定可信 `actor.id` 必须是字符串。修订版发现两个引用不同、JSON 表示相同的对象身份会碰撞，且把生产可利用性保留为条件。复验得到第一用户 A、第二用户也收到 A，跨引用返回成立。三组该题统一排除，保留原题、原答案和轨迹，不事后改题冒充原成绩。详见 [裁决更正](2026-09-28-holdout.correction.json)。生成器现为此题附上 `scoreEligible:false` 与适用范围，材料本身保持原样。
4. 附带问题仍存在：current 在路由防护题误述数组形式操作名的返回状态；baseline 对部分异常/共享引用风险的标题比正文证据更强；revised 的缓存报告引用不存在的第 2/3 行，但所引函数和代码确实在第 1 行。baseline 与 revised 提议用分隔符拼接缓存键，若两部分允许该分隔符仍可能碰撞，修复建议也需要验证。这些均不能被核心通过分掩盖。

## 验证与局限

TypeScript 编译与仓库 12 项测试通过，含大写证据 ID、大小写不匹配、重复 ID、案件 ID 限制、技能示例经真实工具保存读取。生成器独立运行完成 12 题/10 个执行检查；原实验 114 份输入文件逐一比对未改变。官方技能校验脚本因缺少 PyYAML 未能运行，已用现有 YAML 解析器检查 frontmatter 和引用，并用单元测试验证示例。

题目由同一开发者准备，代码很小且多为单行，TASK 明示了安全不变量；每题每组仅一次，不能证明统计显著改善，也不能代表真实仓库发现率。缓存身份发现说明原始答案不是绝对真值，10 个执行检查也不能证明覆盖了全部合法输入。
